# Accounting & reporting capability matrix

Date: 2026-10-09 · Scope: Odoo 19 Community + the nine pinned OCA 19.0 repos + NCollection modules ·
Companion: [REPORTING_ARCHITECTURE_RECOMMENDATION.md](REPORTING_ARCHITECTURE_RECOMMENDATION.md)

**Verdict: NCollection reporting is NOT yet a complete, professional ERP reporting system.** The financial
statements, ledgers, ageing, statements and tax analysis are complete and verified to a high standard. The gaps
are elsewhere, and they were not what the test suite could see:

1. **Sales, Purchases and Inventory reports existed but nobody could open them.** Their menus are gated on
   Odoo's *Administrator* groups, which no NCollection role carries, so those hub categories were **empty for
   every role, Owner and CEO included**. Only a superuser (who holds every group) saw them — which is why
   every earlier test, run as `admin`, passed. Fixed for Sales and Inventory; **Purchases is still invisible to
   Owner / CEO / Manager** because no role holds Purchase — a role-matrix decision (D-1, not taken here).
2. **A report menu being visible or hidden proved nothing about authorisation.** Server-side testing found the
   OCA ledger wizards open to every internal user (a salesperson or department manager could pull the whole
   general ledger). Fixed and guarded by tests that attempt the call.
3. **7 distinct reports are genuinely missing** (8 rows: Sales vs Target is listed under both Sales and Management) and 13 rows are only partly covered; the largest real gaps are
   Stock Aging / Slow-moving / Turnover, Sales-vs-Target, customer/product profitability and payment history.

## How to read this

* **Method.** Every row was read from the running system (atlas, wasla and a seeded scratch tenant), the pinned
  checkouts in `./oca`, or the module code — not assumed. Where something could not be measured it says
  "not benchmarked" rather than guessing.
* **SOURCE classes:** `ODOO_NATIVE` · `OCA` · `NCOLLECTION_EXISTING` · `MISSING` · `DUPLICATE` · `PARTIAL`.
* **Strategy letters (one primary per row):** **A** keep Odoo native · **B** Odoo native through NCollection
  integration (a hub entry / menu, no new report) · **C** adopt OCA · **D** adopt OCA through the NCollection
  adapter · **E** keep/build NCollection custom · **F** combine existing sources only where genuinely necessary.
* **EFFORT:** `0` nothing to do · `S` ≤ 1 day · `M` 2–4 days · `L` ≥ 1 week.
* **✓** = verified in this audit (server-side or in a real browser); a cell without ✓ is read from code.

### What is genuinely MISSING (7 reports, 8 rows)

Collection / dunning · Customer Payment History · Vendor Payment History (the data is native — a hub entry
fixes it) · Sales vs Target (two rows) · Stock Aging · Slow-Moving Items · Working Capital. (Inventory Turnover
has a KPI but no report: PARTIAL.)

### Not verified (stated, not hidden)

* OCA modules in repos that are **not pinned** (sale-reporting, purchase-reporting, stock-logistics-reporting,
  account-invoice-reporting) were read from their GitHub `19.0` branch manifests only — never installed here.
* Native analysis views (sale / purchase / stock) were **not benchmarked at volume**; they are SQL views.
* OCA reports' PDF/RTL rendering and performance were not measured except the Trial Balance pilot.
* The toolbar **Print** click could not be completed in a browser on the development machine: Internet Download
  Manager answers Odoo's PDF download with an empty 204 for every browser (see the PDF root cause in the
  recommendation document). The request the client sends was replayed outside the browser and returns a valid PDF.

## Notes on specific cells

* **ACCESS CONTROL — D-1, D-2, D-3 are decisions, not defects I changed.** D-1: no NCollection role holds a
  Purchase group. D-2: Odoo core lets the Sales and Manager roles read `account.move.line` (journal items), which
  contradicts the role matrix's "Manager gets no financial visibility"; the reports are protected, the raw model
  is not. D-3: every internal user can read stock moves and quants (Odoo default). All three are in the
  recommendation document with a proposed resolution.
* **Perf.** GL PDF time is dominated by wkhtmltopdf (232 pages ≈ 42 s); the backend run is ≈ 1 s. A request-timeout
  budget of ≥ 60 s is needed for very large ledgers, or a queued export.
* **Arabic.** OCA ships Arabic for `account_financial_report` (partial) and `account_asset_management` only;
  `partner_statement`, `account_tax_balance` and `mis_builder` have **no Arabic**.
